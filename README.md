# polycubes.org

The website of the [Polycube Tiling Census](https://github.com/polycubing/census): one page per shape, an index per size, pages per tag, and the prose. Static HTML generated by Ruby from the census's own records, served by GitHub Pages at [polycubes.org](https://polycubes.org).

## How it works

The census is the database. `script/build` walks `../census/data`, one `shape.json` at a time, and writes `public/`. A shape's page carries its own geometry: the shape, the tiling chunk or corona witness that backs its verdict, all precomputed as lists of cells with the census's own `Rotation` and `Assembly` and inlined as JSON. The viewer, `assets/viewer.js`, is 200 lines of plain WebGL that draws cubes. Meshes for download come from the census repo through jsDelivr. Nothing is fetched at page load but the stylesheet and the viewer.

Shape ids are paths: `/9/2127/` is the staircase, here and in the data and in any paper.

- `lib/site/` the generator: `Record` (a shape and what to say about it), `Layers` (what the viewer draws), `Catalog` (every shape, streamed), `Pagination`, `Page` (ERB in a layout), `Markdown`, `Highlight`, `Build`.
- `templates/` ERB for the layout, shape, listing, home, and prose pages.
- `content/` prose as markdown, and `names.yml`, the nicknames. Edit these freely. The next build carries the change.
- `assets/` the site's own stylesheet and the viewer.
- `vendor/` Bootstrap, as files.

## Running it

```sh
script/bootstrap     # needs the census checked out at ../census
script/build         # or script/build 8 while iterating
script/server        # http://localhost:8000/
script/test          # specs + rubocop
```

Ruby version is pinned in `.ruby-version`. The build takes a few minutes for all 56,463 shapes.
